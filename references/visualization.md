## 1. 图表设计原则

每张重要图先写一句“这张图要让评委看见什么”。如果这句话写不出来，说明图可能没有必要。

图表优先承担以下任务之一：

- 解释机理
- 展示变量关系
- 证明模型合理
- 呈现最优方案
- 揭示阈值/策略切换
- 展示误差与稳健性
- 对比基准与改进

## 2. Overview 图

不要画粗糙流程图。优先展示三层：

- **问题层**：四问如何递进；
- **模型层**：M0 如何推广为 M1/M2；
- **信息层**：数据/参数/结果如何传递和反馈。

设计规则：

- 节点 5–9 个为宜；
- 不交叉、不重叠；
- 箭头含义明确；
- 数据流和模型流可用不同线型/颜色；
- 最好体现“验证/不确定性反馈”，而不只是单向链。

## 3. 图形选择

| 要表达的内容 | 优先图形 |
|---|---|
| 两变量关系 | 散点 + 拟合/理论曲线 |
| 参数敏感性 | 折线、误差带、热力图 |
| 策略切换 | 相图、分区图、阈值曲线 |
| 时间/迭代 | 折线、收敛曲线 |
| 多方案比较 | 点图、条形图、雷达图仅谨慎使用 |
| 空间地形 | 等高线、热力图、曲面 |
| 路径规划 | 空间路径 + 约束边界 |
| 网络结构 | DAG、状态转移图 |
| 概率分布 | 密度、CDF、区间图 |
| 模型误差 | 残差、Q-Q、箱线、误差棒 |

## 4. 创意表达

优先设计“一个图展示三层信息”的图，而不是堆很多普通图。

### 例：策略相图

若两个参数共同决定最优方案，画

\[
(\theta_1,\theta_2)\mapsto\text{最优策略}
\]

用不同低饱和区域表示方案 A/B/C，比多张单参数灵敏度折线更直观。

### 例：基准—改进—真实数据

同一图中用：

- 蓝色实线：理论基础模型；
- 橙色点：观测数据；
- 青绿色实线：修正模型；
- 浅灰误差带：置信区间。

一张图同时完成拟合、改进与验证。

### 例：最优路径图

除最优路径外同时标：

- 可行域边界；
- 风险/禁入区域；
- 起终点；
- 关键拐点或局部最优区；
- 必要时用颜色表示局部代价。

## 5. 配色与排版

推荐低饱和、论文风格配色：

- 深蓝 `#3B6FB6`
- 青绿 `#4C9F91`
- 暖橙 `#D98C4A`
- 紫灰 `#7D789A`
- 风险红 `#C65A5A`（只用于异常/超约束）

规则：

- 一张图主要颜色 2–4 种。
- 同一语义在全文保持同一颜色。
- 背景白色或极浅灰。
- 网格线弱化。
- 坐标轴、图例、单位完整。
- 线宽与点大小适中，不做商业 PPT 风格。
- 允许黑白打印时仍可通过线型/标记区分。

## 6. 表格规范

默认三线表。重要表格应能脱离正文独立理解。

### 最终结果表必须包含

- 情形/方案
- 最优决策
- 核心目标值
- 必要约束或误差
- 如有必要，加基准方案或次优差距
