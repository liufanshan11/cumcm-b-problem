# B 题端到端工作流

## 目录

1. 赛题输入检查
2. 0–2 小时结构拆题
3. 基础模型阶段
4. 求解与验证阶段
5. 论文同步写作阶段
6. 最终成稿阶段

## 1. 赛题输入检查

先整理以下材料并标注来源等级：

- 赛题正文与附件：最高优先级。
- 当前年份官方规则/评分提示：若有则优先读取。
- 用户指定专家讲评、优秀范文、行业标准：用于启发和校验。
- 历年 B 题经验：只用于判断常见结构，不得替代当前题意。

建立“事实—假设—推断”清单。任何不在题面或附件中的数值都不得悄悄当作事实。

## 2. 0–2 小时结构拆题

### 2.1 每问六要素

对每问写出：

- 输入数据/已知量
- 输出目标
- 未知参数
- 决策变量
- 约束
- 与上一问的联系

### 2.2 找主线

优先寻找以下贯穿全文的对象之一：

- 同一核心机理公式
- 同一状态变量或质量指标
- 同一评价函数/目标函数
- 同一几何关系
- 同一概率参数
- 同一网络/流程结构

若四问暂时看似无关，先判断是否存在“理想 → 现实”“特例 → 一般”“估计 → 决策”“基础模型 → 优化”“确定参数 → 不确定参数”的递进。

### 2.3 预测后续问题

第一问完成后主动检查：

- 哪个假设最可能在下一问被放宽？
- 哪个公式最值得一般化？
- 哪个参数可能需要从附件估计？
- 哪个结果可能转为目标函数或约束？

## 3. 基础模型阶段

### 3.1 建立最小可行模型 M0

只保留能回答当前问题的必要因素。写清：

- 变量定义
- 模型假设
- 适用条件
- 推导过程
- 最终方程组/目标与约束

### 3.2 先化简再求解

依次检查：

1. 是否存在解析关系？
2. 是否存在单调性、凸性、对称性或支配关系？
3. 是否能分区、分层、分阶段、分子问题？
4. 是否可用图/DAG/动态规划表示？
5. 只有前面无法有效化简时，再考虑启发式搜索。

## 4. 求解与验证阶段

### 4.1 求解

算法说明必须回答：

- 求解的数学对象是什么？
- 为什么该算法与对象匹配？
- 停止条件是什么？
- 是否存在局部最优/初值依赖/近似误差？

### 4.2 验证优先级

优先组合：

- 手算小例 + 程序结果
- 解析结果 + Monte Carlo
- 主算法 + 独立算法
- 模型预测 + 实际数据
- 基础模型 M0 + 修正模型 M1

### 4.3 现实修正

只有在以下至少一项成立时升级模型：

- 基础模型对数据出现系统偏差；
- 题目明确加入新现实条件；
- 参数量级显示某效应不可忽略；
- 目标/约束发生实质变化。

不要为了“高级”一次性加入所有因素。

## 5. 论文同步写作阶段

不要等模型全部做完后才写论文。每完成一问同步产出：

- 问题分析段
- 模型示意图
- 关键推导
- 最终模型方程组
- 求解流程
- 结果表/图
- 结果解释
- 验证
- 与下一问的承接句

这样可尽早发现符号、口径和结果不一致。

## 6. 最终成稿阶段

### 6.1 主论文节奏

建议 25–29 页，优先 26–28 页。不要靠空白或巨图凑页数。

### 6.2 最后统一检查

- 摘要是否只保留动机、方法、核心结果和验证？
- 问题分析是否真正分析而不是复述？
- 所有核心模型是否集中总括过？
- 所有表格是否能独立阅读？
- 所有重要图是否有明确洞察？
- 结论是否回答题目而不是重复全文？
- 参考文献是否覆盖所用核心方法和领域依据？
- 代码能否复现关键结果？
